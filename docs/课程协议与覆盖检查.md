# 知行拾课 iOS 课程协议 v2

v2 是原版 `zhixing-study-pack` 的扩展，保留章节、知识点、四种题型、稳定 ID、revision 和进度兼容规则。应用继续导入 schemaVersion=1 的旧课程及原版学习备份；旧课程显示“未声明完整大纲”，不会伪称完整覆盖。

## 范围与来源

新增 `scope: {title,boundary,sources,syllabus,exclusions}`。`sources` 每项有唯一 `id`、`title`、`locator`。`syllabus` 每项有唯一 `id`、`title`、`sourceRefs`、`pointIds`。每个知识点新增 `sourceRefs`、`syllabusIds`，大纲与知识点必须双向对应。明确不覆盖的主题在 exclusions 中说明 title 和 reason，没有时写 []。

只对经用户确认的资料与大纲建立覆盖清单。程序无法判断作者是否遗漏了教材原文里的某项，也无法证明答案正确。软件验证的是锁定清单与实际内容的结构对应；答案须独立审校。用户未提供范围时，先确认范围，不宣称穷尽整个学科。

## 独立题库

每题新增 `primaryPointId`、`skill`、`sourceRefs`、`solutionSteps`；客观题必须有 `optionExplanations`，每个选项均给具体原因。skill 为 recall/application/transfer/misconception/synthesis。其余题型字段沿用 v1。

每个知识点至少五道以它为 primaryPointId 的独立题（综合题不计入）：recall 至少两道，application、transfer、misconception 各至少一道。每章有两个以上知识点时，另外至少两道 synthesis，且每题关联两个以上本章知识点。题干不能完全重复。需要更多题目才能覆盖的方法/条件分支，应增加题量；最低数量并不证明教学完整。

## 分卷

`zhixing-study-part` 的 schemaVersion=2，字段为 `header`、`partIndex`、`totalParts`、`chapters`、`questions`。header 为完整课程顶层元信息（含 scope，不含 chapters/questions），各卷必须完全相同。序号 1..totalParts，最多 100 卷。按卷序合并章节/知识点/题目；同章可拆卷但 id/title/summary 要一致，知识点及题目不得重复。

未收齐的分卷只暂存，不进入书架。收齐后先统一做结构、引用、题量、LaTeX 校验，再经用户确认后原子导入。最终卷失败时，原书架与原暂存不变。重复导入相同卷不增加数量；同序号冲突时拒绝覆盖。

## 数据与数学

单门完整课程最多 8 MiB、3000 知识点、12000 题、5000 处公式；全部已导入课程最多 100 门、32 MiB；含分卷暂存的原生保存与备份最多 40 MiB。浏览器预览的可用存储由浏览器额度决定，通常小于原生应用。超限按模块建不同课程 ID，不能删掉应有内容。

LaTeX 使用 `\( ... \)`、`\[ ... \]` 等配对分隔符；formula 字段直接为 LaTeX。JSON 文本中的每个反斜杠必须双写。KaTeX 和字体离线打包；禁止宏定义、外链与 HTML 注入。独立公式单独横向滚动。

## 稳定更新

同一课程保留 id 并增加 revision；保留知识点与题目 ID。内容未变的阅读和作答记录继续保留，题目/答案/推导/评分要点改变后需重做。新课程使用新的 id。简答、证明与推导采用参考答案和 rubric 自评。

## 校验

运行 `node scripts/validate-course.cjs examples/电路基础_完整覆盖示例.zhixing.json`。分卷依次传入全部文件；校验工具也支持多门独立课程。未收齐分卷返回失败，不报告为完整课程。

完整示例含六个知识点、30 道独立配套题、六道综合题。它是协议示例，范围不等于整门电路课程。
